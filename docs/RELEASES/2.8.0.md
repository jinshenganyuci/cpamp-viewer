# 2.8.0 发布说明

修复多 CPAMP 仅合并配额页的问题。已有 `VIEWER_QUOTA_SOURCES` 配置自动扩展到各只读页面，无需新增配置文件或启动脚本。

## 变更

- 合并仪表盘、用量分析、请求监控及账号/调用密钥筛选。相同邮箱或相同 Key 在不同实例中保持独立，卡片和选项显示实例名称。
- 合并 Access Guard 公开 Key 额度。`ACCESS_GUARD_PUBLIC_ALL=true` 自动覆盖所有 CPAMP；主实例明确名单不复用到副实例。额外实例可选 `access_guard_public_all` 或 `access_guard_public_keys` 分别控制。
- Codex 凭证展示重置卡剩余次数及每张到期倒计时，仅查询，不消费或重置。数量已知而详情缺失时说明不完整，不把查询失败当作零。
- 合并用量状态和模型价格状态；价格按实例使用，缺失或冲突不套用主实例价格。
- 全局请求分页保留各实例进度，校验游标与筛选；部分来源故障保留健康数据并提示，翻页期间历史页改变则要求刷新。
- 多来源统计仅合并能准确计算的指标。缺少有效样本数的平均延迟、P95 等显示未知；有限榜单标注范围。
- 修复账号脱敏模式下 hover 仍显示原邮箱、同名账号实时记录误归组的问题。

## 升级

镜像：

```text
jinshenganyuci/cpamp-viewer:2.8.0
jinshenganyuci/cpamp-viewer:latest
```

已使用 `latest` 且已配置第二个 CPAMP 的部署保留原 `.env` 和 Compose，执行：

```bash
docker compose pull cpamp-viewer
docker compose up -d --no-deps cpamp-viewer
```

固定版本用户将 `image` 标签或仓库 `.env` 中的 `CPAMP_VIEWER_VERSION` 改为 `2.8.0`。使用 Compose 叠加文件的部署继续带上原来的 `-f` 参数。

首次添加第二个 CPAMP 的 `.env` 用法、按实例公开 Key 的选项见 [README](../../README.md#接入多个-cpa--sub2api)。不需要新脚本、离线导入或更换镜像仓库。

## 边界

Sub2API 继续只补充账号额度；`/health` 仍检查主 CPAMP。其他页面缺少的上游接口或数据会提示不可用。来源汇总是配置实例的合计，相同真实账号如果在两个实例都有配置，会分别显示；请求数据若被上游重复导入两个数据库，也会分别计入。

管理密钥、认证文件正文、私有重置卡 ID 和上游错误正文不返回浏览器。Viewer 不执行账号启停、Key 编辑、额度重置、重置卡消费或管理端迁移。Windows 产物为交叉编译，未做 Windows 实机验收。
