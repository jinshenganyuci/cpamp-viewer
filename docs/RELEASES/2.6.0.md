# 2.6.0 发布说明

本版将 [PR #1](https://github.com/jinshenganyuci/cpamp-viewer/pull/1) 的 Sub2API 账号额度来源纳入正式镜像。

## 新增与修复

- 配额管理可同时展示 CPA Manager Plus 与 Sub2API 账号，卡片标明来源。一个来源失败时尽量保留另一来源的数据。
- Sub2API 的 Anthropic OAuth/Setup Token 读取被动用量快照；OpenAI Codex 使用账号列表中已有的 5H/7D 窗口；API Key 账号展示明确配置的额度。没有有效数据时显示暂无快照或未知，不主动探测模型、刷新凭据或修改账号。
- 修复 Spark 额度被标为普通 Codex 的问题，按原有额度池分别展示。
- 修复 Anthropic 未采样额度被显示为剩余 100% 的问题，缺少有效使用率时保持未知。
- 新增 `compose.sub2api.yaml` 叠加配置；部署包包含此文件。README 补全管理员密钥文件、权限、启动和升级方法。

## Docker 与升级

镜像平台为 `linux/amd64`：

```text
jinshenganyuci/cpamp-viewer:2.6.0
jinshenganyuci/cpamp-viewer:latest
```

仅使用 CPAMP 的用户保持原有配置，将 `.env` 中 `CPAMP_VIEWER_VERSION` 改为 `2.6.0` 后拉取并重建即可。

现有自定义 Compose 可直接映射 `SUB2API_BASE_URL` 和 `SUB2API_ADMIN_API_KEY`，使用原有启动命令；[README](../../README.md#现有自定义-compose只加两项环境变量) 给出最少改动示例。直接密钥与文件密钥两种方式选择一种即可。

使用仓库自带的文件密钥方案接入 Sub2API 时，新增 `SUB2API_BASE_URL` 和 `SUB2API_ADMIN_API_KEY_PATH`，写入独立的 **Sub2API 管理员 API Key** 文件，然后始终使用双文件命令：

```bash
docker compose -f compose.yaml -f compose.sub2api.yaml pull cpamp-viewer
docker compose -f compose.yaml -f compose.sub2api.yaml up -d --no-build --no-deps cpamp-viewer
```

Sub2API 是可选的第二个来源，仍需有效的 CPAMP 地址和 Admin Key。普通模型调用 API Key 不能代替管理员 API Key。后续升级或修改参数时也保留 `compose.sub2api.yaml`，否则重建后的容器不包含该来源配置。完整 `.env` 和密钥操作见 [README](../../README.md#同时接入-sub2api)，离线方式见 [高级部署说明](../DEPLOYMENT.md#同时接入-sub2api)。

离线包使用本地镜像标签 `cpamp-viewer:2.6.0`。先校验并加载 Linux 镜像，再使用 `-f docker-compose.viewer.yml -f compose.sub2api.yaml up -d --no-build`。下载完整性以 Release 的 SHA-256 文件为准。

## 验证与边界

构建流程包含前端类型检查、测试、样式检查和生产构建、前端管理路径扫描、Go 测试与静态检查、Linux Docker 镜像及 Windows 交叉编译。具体运行结果见对应 GitHub Actions 和发布记录，不以构建流程描述代替通过结论。

Sub2API 适配基于固定只读接口与受控测试数据，不代表已经连接任意真实 Sub2API 部署或提供方账号完成验收。Windows 程序为交叉编译产物，未做 Windows 实机验收。`/health` 继续检查 CPAMP，Sub2API 状态需在配额页确认。

管理员凭据仅留在服务端；浏览器不接收原始密钥、Token、账号 ID 或上游错误正文。Sub2API 最多读取 2000 个账号，超出时显示来源不可用，避免静默遗漏。原有 CPAMP、Access Guard 公开范围及只读边界保持不变。
