# 2.7.0 发布说明

本版将 [PR #2](https://github.com/jinshenganyuci/cpamp-viewer/pull/2) 的多实例额度来源纳入正式镜像。可直接使用 `jinshenganyuci/cpamp-viewer:latest`，无需本地构建。

## 新增与修复

- 配额管理支持多个 CPA / Sub2API 实例；卡片显示来源名称并可按名称搜索。同一邮箱在不同实例中分别保留。
- 新增 `VIEWER_QUOTA_SOURCES` 内联 JSON 和 `VIEWER_QUOTA_SOURCES_FILE` 文件配置，二选一。现有主 CPAMP、`SUB2API_*` 和 Access Guard 配置继续兼容。
- 含主 CPAMP 和原 Sub2API 在内最多 16 个来源，最多同时读取 4 个来源；某个来源失败时保留其他可用来源，不泄露上游错误正文。
- Sub2API 优先显示已有邮箱和原始套餐，按实际时长识别已保存额度窗口，保留普通 Codex / Spark 区分，不推测不存在的 5H 窗口或把未知额度显示为满额。
- 脱敏模式同时遮罩账号文字和悬停提示，避免悬停显示完整邮箱。
- Docker 部署包增加 `compose.quota-sources.yaml` 和无真实凭据的 JSON 示例。

## Docker 与升级

镜像平台为 `linux/amd64`：

```text
jinshenganyuci/cpamp-viewer:2.7.0
jinshenganyuci/cpamp-viewer:latest
```

现有自定义 Compose 保留原端口、密钥和其他配置，镜像可继续使用 `latest`。需要增加第二个 CPAMP 时，在原服务的 `environment` 中添加：

```yaml
      VIEWER_QUOTA_SOURCES: ${VIEWER_QUOTA_SOURCES:-[]}
```

在原 `.env` 追加一行：

```dotenv
VIEWER_QUOTA_SOURCES='[{"type":"cpamp","name":"CPAMP 二号","base_url":"https://cpamp-two.example.com","admin_key":"替换为二号CPAMP的AdminKey"}]'
```

将示例地址和密钥换成第二个实例的管理信息；只填写新增来源，不重复原主 CPAMP 或原 Sub2API。`.env` 必须有对应 Compose 映射，且不得同时设置 `VIEWER_QUOTA_SOURCES_FILE`。然后执行：

```bash
docker compose pull cpamp-viewer
docker compose up -d --no-deps cpamp-viewer
```

使用仓库自带 Compose 时，将 `CPAMP_VIEWER_VERSION` 改为 `2.7.0` 或 `latest`。文件方案和已有 Sub2API 叠加方案见 [README](../../README.md#接入多个-cpa--sub2api)，后续重建应保留原来使用的叠加文件。离线镜像标签为 `cpamp-viewer:2.7.0`，需先校验、加载，再使用 `docker compose -f docker-compose.viewer.yml up -d --no-build`。

## 验证与边界

构建流程包含前端类型检查、测试、样式检查与生产构建、只读边界扫描、Go 测试与静态检查、Linux Docker 构建及 Windows 交叉编译。实际通过结果以本次 GitHub Actions 和发布记录为准，下载文件以 Release 的 SHA-256 校验文件为准。

多来源仅作用于配额管理，其他页面及 `/health` 继续读取主 CPAMP。管理员凭据留在服务端，浏览器不能修改账号或重置额度。受控测试不能代替对任意真实上游部署的连接验收；Windows 为交叉编译产物，未做 Windows 实机验收。
